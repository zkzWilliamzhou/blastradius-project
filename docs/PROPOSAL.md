# 立项书：BlastRadius（`br`）

日期：2026-11-10 · 状态：立项并立即执行 · 作者：讯飞星火

## 1. 问题（为什么值得做）

2025–2026 年，软件开发的主角从"人敲命令"变成"agent 敲命令"。Claude Code、Cursor、
Codex、通义灵码这类工具每天在你的机器上执行成百上千条 shell 命令；沙箱、审批弹窗
和 `--dangerously-skip-permissions` 之间的差别，往往只是"你有没有看清那行命令"。

现有的安全层有两个缺口：

1. **面向人**：`shellcheck` 检查语法正确性，`trivy` 检查依赖漏洞，都不回答
   "这条命令一旦执行，最坏会发生什么"。
2. **面向拦截**：各家 agent 自带"危险命令黑名单"（`rm -rf /`、`dd of=/dev/sda`），
   三条正则、写死在源码里、不可审计、不可定制、不做组合判断——
   完全看不出 `curl … | sh`、`cat ~/.ssh/id_rsa` 配合 `curl -d @-` 的杀伤力。

缺的是**面向 agent 的、可解释、可策略化、可离线运行的事前影响评估**：
给一条命令，输出它触碰哪些能力（写盘/删除/提权/外联/凭据/发布/持久化）、
最坏情况是什么、评分多少、该放行还是拦下——并且给出证据和替代方案。

## 2. 世界上有没有同类

粗略调研（离线环境，凭既有知识，不做虚构引用）：

- Greshake 等 2023 年的间接提示注入研究、各类 "agent guardrail" 产品（如
  Invariant Labs、Guardrails AI）主要做 **LLM 输入输出**层面的过滤。
- agent 框架内置的 command allow/deny 是 **精确字符串匹配**，不做 shell 语义解析。
- `shellcheck` / `bashate` / `shfmt` 是**静态代码质量**工具，不是风险模型。
- `sudo` 的 `sudoers` 是**执行期**强制，粒度到程序，不到"这条命令想干什么"。

结论：**"shell 命令的影响面静态分析 + 可审计策略引擎 + agent hook 协议"** 这个
组合，作为独立、零依赖、可离线、可解释的组件，市场上没有一个明确的占位者。
不宣称"世界首创"（无法离线核实），但明确不做已有工具的复刻。

## 3. 差异化（凭什么能打）

| 维度 | 常见做法 | BlastRadius |
|---|---|---|
| 判断依据 | 正则匹配整串 | 词法 + 结构解析（引号/转义/管道/heredoc/`$()`/包装器） |
| 输出 | 一个布尔值 | 规则 ID + 能力标签 + 证据 + 最坏情况 + 修复建议 |
| 组合风险 | 无 | 跨段聚合（`cat 密钥 \| curl -d @-` = 外泄） |
| 可定制 | 改源码 | JSON 策略：能力/程序/路径 glob/严重度/文本片段 |
| 接入方式 | 各家各写 | CLI + 退出码 + Claude Code PreToolUse hook JSON |
| 依赖 | 一堆 | 0 依赖，纯 stdlib，Python ≥3.9 |
| 可验证 | 手工 | 内置 169 条回归语料，`br selftest` 自证 |

## 4. 目标（可验收，不说空话）

1. 对 169 条真实世界命令（含安全与危险孪生对）给出稳定判断，误报率 < 5%。
2. 单条命令分析 p99 < 5ms，1MB 恶意输入不崩、不卡（无 ReDoS、无递归失控）。
3. 工具自身**绝不执行**被分析的命令（纯字符串分析），无 `eval`/`os.system`/`subprocess`。
4. 策略引擎可把 `rm -rf /tmp/**` 放行、把 `aws s3 rm --recursive` 拦下。
5. `pip install .` 后 `br check '…'` 可用；hook 模式可直接接 Claude Code。

关于"105k stars"：stars 取决于社区分发与时机，不是代码能单方面决定的结果；
我能控制的是**质量、可用性、可解释性和零依赖分发**。本项目按"值得被 star"的标准做，
不伪造数据、不刷量。

## 5. 非目标

- 不做沙箱、不做执行、不做运行时监控（那是 seccomp/eBPF 的活）。
- 不追求 100% shell 语义（不做变量展开、不做 glob 展开），解析失败**显式降级**
  为"低置信度 + 原始文本规则"，绝不静默放行。
- 不替代 `sudoers`；它是**建议层**，不是强制层。

## 6. 风险

| 风险 | 应对 |
|---|---|
| 误报导致用户关掉工具 | 严重度分级 + 策略可调 + 只对"宽路径/组合"报警，不对 `rm -rf node_modules` 报警 |
| 漏报造成虚假安全感 | 输出 `confidence`，解析降级时明确标注，文档写清边界 |
| 规则被绕过（编码、变量、别名） | 检测混淆手法本身（`base64 -d \| sh`、`eval`、`$IFS`），并标注"不可判定" |
| 规则库腐化 | 语料回归 + `selftest` + 每条规则一个反例（孪生用例） |
